# The demo and board layer

Everything in this directory is a way of showing the primitive, not the primitive
itself. Nothing here belongs in a claim about Tagma, and a bug here does not
change what the decoder does.

| | |
|---|---|
| `tagma_demo_top.v` | the board demo: a code point on switches, the three axes on LEDs |
| `tagma_demo_top_tb.v` | the demo top against the golden anchors |
| `tagma_pipe_top.v` | the streaming decoder as a top, so place and route reports a clock |
| `tagma_pipe_check_top.v` | the pipeline against the combinational unit, on the die |
| `tagma_pipe_verify_top.v` | the sweep checksum, against the anchors `tagma_core` writes |
| `tagma_volume_verify_top.v` | the coordinate values of a volume, against the same anchors |
| `tagma_pipe_pll.v` | generated by `ecppll` for the 40 MHz check image |
| `led_check_top.v` | the RGB channels one combination at a time, to place a fault |
| `stage_check_top.v` | the stage pins straight onto the channels, to place a fault |

`../` holds what the primitive is: the decoder, the pipeline, the composer, the
distance, the segment store, their testbenches, and `golden_anchors.hex`.

A file that moves in the other direction needs a reason a claim depends on it.
